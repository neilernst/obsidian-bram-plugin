# Bram Project Tracker 0.1.0 beta

This is an early beta for invited testers. It is distributed as a GitHub pre-release only and is not listed in the Obsidian Community directory. The repository is private, so testers need repository access to download the release.

## What's included

- A project overview with active Bram Worklist items, Git branch and working-tree status, recent commits, and a 30-day line-change sparkline.
- A `bram-project` code block that embeds Worklist, Git, and recent GitHub issue details in a registered project note.
- Project registration and editing, including choosing the Git remote used to identify the GitHub repository.
- Read-only access to the five most recently updated open GitHub issues. Public repositories do not need a token; private repositories require a fine-grained token with Issues read-only permission.

## Install

1. Download `main.js`, `manifest.json`, and `styles.css` from the GitHub release tagged `0.1.0`.
2. In your vault's configured plugin folder (by default `.obsidian/plugins/`), create `bram-project-tracker` and place those files there.
3. In Obsidian, open **Settings → Community plugins**. Turn off **Restricted mode** if prompted, then enable **Bram Project Tracker** under installed plugins.

This release is for Obsidian desktop. Git must be installed and available to Obsidian for local repository details. The manifest declares Obsidian `1.0.0` as the minimum version; this beta has not completed full runtime acceptance testing.

## What to try

- Register a project and verify its overview, linked note, selected Git remote, and refresh behavior.
- Add an empty `bram-project` code block to the linked note and check that its Worklist, Git, and issue details match their sources.
- Try a public GitHub repository without a token and a private repository with a narrowly scoped read-only token, if available.
- Report incorrect values, unreadable states, or unexpected changes to notes or repositories.

## Known limitations and safety

- The recorded acceptance run was partial: the TypeScript preflight and current production build passed, but Obsidian UI, note rendering, and live GitHub issue checks were not completed.
- A static security audit found that `git status` can run a repository-configured `core.fsmonitor` command. Register only repositories whose local Git configuration you trust. See the [security audit](../security-audit.md) and [remediation checklist](../security-remediation-checklist.md).
- A GitHub token is stored in Obsidian plugin settings data and may be included in vault syncs or backups. Use a fine-grained token scoped to the needed repositories with Issues read-only permission. Clear and save the token to remove it from plugin settings, and revoke it through GitHub if it may have been exposed.
- The plugin makes read-only GitHub API requests for issue data. It does not send telemetry.
